첫 문서를 표시한 뒤 정확한 시그니처와 준비 조건을 찾을 때 사용하세요. 애플리케이션 코드가 직접 호출하는 브라우저 API와 모든 컨트롤러·React 핸들 메서드를 다룹니다. Core와 Viewer는 DOM API가 필요하므로 서버 사이드 렌더링 중에는 실행되지 않습니다.

## 패키지 맵

| 패키지 | 용도 | 대표 API |
| --- | --- | --- |
| `@imposia/react` | React 통합 | `ImposiaPageViewer`, `ImposiaDocument`, `ImposiaPublicationViewer`, 두 수명 주기 훅 |
| `@imposia/core` | 프레임워크에 종속되지 않는 페이지네이션과 Publication | `mountPageDocument`, `mountPublication`, `prepareDocument` |
| `@imposia/viewer` | 확정 페이지 또는 PDF 표시 | `mountPageViewer`, `mountViewer`, 딥 링크 도우미 |
| `@imposia/client` | 프레임워크에 종속되지 않는 통합 진입점 | 주요 Core·Viewer 통합 API를 다시 내보냅니다. |

React 패키지를 사용할 때는 `@imposia/react/styles.css`를 한 번만 불러오세요.

```ts
import "@imposia/react/styles.css";
// 또는 import "@imposia/client/styles.css";
```

## React 컴포넌트와 훅

### `ImposiaPageViewer`와 `ImposiaDocument`

`ImposiaPageViewer`는 Core 페이지 문서를 마운트한 뒤 첫 문서가 확정되면 Page Viewer를 연결합니다. `ImposiaDocument`는 공개 prop과 핸들 타입이 같은 호환 래퍼입니다. `ImposiaDocumentProps = ImposiaPageViewerProps`, `ImposiaDocumentHandle = ImposiaPageViewerHandle`입니다.

```tsx
<ImposiaPageViewer ref={ref} source={source} />
```

| Prop | 타입 | 설명 |
| --- | --- | --- |
| `source` | `PageSource` | 필수. 페이지로 만들 HTML 또는 light DOM입니다. |
| `sourceRevision` | `string \| number` | 같은 내용으로 판단되는 source를 다시 처리할 때 바꿉니다. |
| `documentOptions` | `PageDocumentOptions` | Core 컨트롤러 생성 설정입니다. |
| `documentOptionsRevision` | `string \| number` | 값이 바뀌면 새 설정으로 만든 컨트롤러와 canonical iframe으로 교체합니다. |
| `viewerOptions` | `PageViewerOptions` | 모드, 배율, 테마, Inspector 설정입니다. |
| `onViewerStateChange` | `(state: PageViewerState) => void` | 페이지, 배율, 요청 모드, 실제 적용 모드, 세대의 변화를 전달합니다. |
| `className`, `style` | `string`, `CSSProperties` | 호스트 `div`의 표시 속성입니다. |
| `onReady` | `(document: PageDocument) => void` | Core 문서와 Viewer가 같은 세대를 표시할 준비를 마치면 호출합니다. |
| `onError` | `(error: unknown) => void` | Core 작업이나 Viewer 바인딩이 실패하면 호출합니다. |
| `onStateChange` | `(state: ImposiaDocumentState) => void` | `idle`, `loading`, `ready`, `error` 전환을 전달합니다. |

`documentOptions` 객체의 참조만 바뀌어서는 설정이 달라지지 않습니다. 새로운 `assetResolver`, 확장 기능, 용지 설정을 적용하려면 `documentOptionsRevision`도 바꾸세요.

#### `ImposiaPageViewerHandle`

| 멤버 | 반환값과 조건 |
| --- | --- |
| `current` | `PageDocument \| undefined`. 준비 전이나 언마운트 뒤에는 `undefined`입니다. |
| `viewerState` | `PageViewerState \| undefined`. 준비된 Viewer의 현재 표시 상태입니다. |
| `goToPage(page)`, `nextPage()`, `previousPage()` | `void`. 현재 확정 문서의 전역 페이지를 이동합니다. |
| `setZoom(zoom)` | `void`. 표시 배율을 제한 범위 안에서 바꿉니다. |
| `setMode(mode)` | `void`. `continuous`, `single`, `spread`로 바꿉니다. 문서가 준비되기 전에 호출하면 예외가 발생합니다. |
| `setSpreadCover(cover)` | `void`. spread에서 1페이지를 단독 표지로 둘지 정합니다. |
| `openInspector()` | `void`. Inspector가 없으면 예외가 발생합니다. |
| `closeInspector()` | `void`. Inspector가 없으면 예외가 발생합니다. |
| `toggleInspector()` | `void`. Inspector가 없으면 예외가 발생합니다. |
| `selectWarning(warning)` | `void`. 현재 세대의 경고만 받습니다. Inspector가 없거나 이전 세대의 경고를 전달하면 예외가 발생합니다. |
| `print()` | `Promise<void>`. 준비 전이나 언마운트 뒤에 호출하면 `Promise`가 거부됩니다. |
| `exportEpub(options)` | `Promise<Blob>`. 준비 전이나 언마운트 뒤에 호출하면 `Promise`가 거부됩니다. |

```tsx
const ref = useRef<ImposiaPageViewerHandle>(null);
<ImposiaPageViewer
  ref={ref}
  source={{ html: "<main><h1>문서</h1></main>" }}
  viewerOptions={{ inspector: true }}
/>;
await ref.current?.print();
```

### `useImposiaDocument`와 `useImposiaPublication`

```ts
useImposiaDocument(props: UseImposiaDocumentProps): {
  hostRef: RefObject<HTMLDivElement | null>;
  state: { status: "idle" | "loading" | "ready" | "error"; document?: PageDocument; error?: unknown };
  controller: PageDocumentController | undefined;
};

useImposiaPublication(props: UseImposiaPublicationProps): {
  hostRef: RefObject<HTMLDivElement | null>;
  state: { status: "idle" | "loading" | "ready" | "error"; publication?: PublicationDocument; error?: unknown };
  controller: PublicationController | undefined;
};
```

두 훅은 `hostRef`, 수명 주기 `state`, 컨트롤러를 반환합니다. 컨트롤러는 마운트 effect가 만들기 전까지 `undefined`입니다. `hostRef`는 하나의 `div`에 연결하세요. `loading`이나 `error` 상태에서도 마지막으로 확정된 문서 또는 Publication이 `state`에 남을 수 있습니다.

`useImposiaDocument`는 페이지 컴포넌트와 같은 `source`, revision, 문서 옵션, 콜백을 받습니다. HTML 원본은 HTML이나 기준 URL이 바뀔 때 갱신하고, light DOM 원본은 노드 참조가 바뀔 때 갱신합니다. `sourceRevision`은 갱신을 강제하고 `documentOptionsRevision`은 컨트롤러를 다시 마운트합니다.

`useImposiaPublication`은 Publication 컴포넌트와 같은 `snapshot`, revision, 옵션, 콜백을 받습니다. `snapshot` 참조나 `snapshotRevision`이 바뀌면 갱신하고, `publicationOptionsRevision`이 바뀌면 컨트롤러를 다시 마운트합니다. 두 훅은 정리 단계에서 컨트롤러를 제거하며 `AbortError`를 수명 주기 취소로 처리합니다.

## Core 페이지 문서

### `mountPageDocument`

```ts
function mountPageDocument(
  container: HTMLElement,
  source: { html: string; baseUrl?: string } | { lightDom: Element | DocumentFragment; baseUrl?: string },
  options?: PageDocumentOptions,
): PageDocumentController;
```

canonical iframe 하나를 즉시 연결하고 준비 세대를 시작한 뒤 컨트롤러를 동기적으로 반환합니다. 첫 문서를 읽기 전에 `await controller.ready`로 확정을 기다리세요. `baseUrl`은 상대 에셋 URL을 `assetResolver`에 넘기기 전에 해석하는 기준입니다. Core는 문서에 작성된 URL을 직접 가져오지 않습니다.

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `css?: readonly string[]` | `[]` | 함께 적용할 CSS입니다. |
| `assetResolver?: AssetResolver` | 없음 | 글꼴, 이미지, 미디어, 스타일시트 요청에 `resolved` 또는 `blocked`로 응답합니다. |
| `page?: PageOptions` | A4, 세로, 20mm | `size`, `orientation`, `margin`을 정합니다. 사용자 크기와 여백은 양의 절대 CSS 길이여야 합니다. |
| `limits?: PageLimits` | 내장 상한 | 입력, 노드, 에셋, 페이지, 레이아웃 작업의 상한을 더 낮춥니다. |
| `headerTemplate`, `footerTemplate` | 없음 | 페이지 머리말과 꼬리말 HTML입니다. |
| `decorateBlankPages?: boolean` | `true` | 의도적으로 삽입한 빈 페이지에 장식을 적용합니다. |
| `experimental?: { footnotes?: boolean; pageFloats?: boolean }` | 꺼짐 | 실험 기능을 명시적으로 켭니다. |
| `extensions?: readonly (PageExtension \| PublicationExtension)[]` | `[]` | 선언한 순서대로 변환, 에셋 정책, 장식, `finalizePage`를 적용합니다. |
| `compose?: { yieldBudgetMs?: number; scheduler?: () => Promise<void> }` | 8ms 실행 예산 | 메인 스레드의 페이지네이션 작업을 나누어 실행합니다. `Infinity`는 스케줄러에 실행권을 넘기지 않습니다. |
| `signal?: AbortSignal` | 없음 | 최초 작업을 취소합니다. |
| `onProgress?: ({ completedPages, pass, provisional: true }) => void` | 없음 | 준비 단계에서 페이지를 할당할 때 현재 수렴 단계의 진행률을 전달합니다. 다음 수렴 단계에서는 완료 페이지 수가 1부터 다시 시작할 수 있습니다. |

스케줄러, 글꼴, 이미지 대기 시간도 실제 경과 시간을 재는
`limits.resourceDeadlineMs`에 포함됩니다. 진행률은 언제나 준비 단계의 잠정
값입니다. 확정된 결과는 `controller.current`에서만 읽으세요.

```ts
type AssetResolver = (request: {
  url: string;
  kind: "font" | "image" | "media" | "stylesheet";
  baseUrl?: string;
  signal: AbortSignal;
}) => Promise<
  | { status: "resolved"; bytes: Uint8Array; mimeType: string; resolvedUrl?: string }
  | { status: "blocked"; reason?: string }
>;
```

`PageLimits` 필드는 `maxInputBytes`, `maxNodes`, `maxAssetBytes`, `maxAssetDepth`, `maxAssetReferences`, `resourceDeadlineMs`, `maxPages`, `maxLayoutPasses`, `maxGeneratedFragments`, `maxGeneratedRecords`입니다. 모두 양의 정수이며 내장 상한보다 클 수 없습니다.

`PageExtension`과 `PublicationExtension`은 동기식 `finalizePage(page, context)`를 구현할 수 있습니다. Core가 장식과 margin box 처리를 마치고 문서를 확정하기 전에 승인된 페이지마다 한 번 실행됩니다. `page.element`는 크기를 측정할 수 있는 실제 페이지 요소입니다. `page.tableFragments`에는 원본과 1부터 시작하는 연속 인덱스를 가진 표 조각이 들어갑니다. `finalizePage`는 `decorateBlankPages` 설정과 관계없이, 의도적으로 삽입한 빈 페이지를 포함한 모든 할당 페이지에서 실행됩니다. 변경 내용은 확정된 iframe에 유지되며, `undefined`가 아닌 값을 반환하면 해당 세대가 거부됩니다.

분할된 표의 이어지는 조각에도 측정한 열 너비를 고정해야 한다면 선택형 `createTableColgroupExtension()`을 사용하세요. Core는 작성된 `<colgroup>`을 항상 유지하지만 기본값으로 열 너비를 새로 만들지는 않습니다.

#### `PageDocumentController`

| 컨트롤러 멤버 | 반환값과 동작 |
| --- | --- |
| `ready` | `Promise<PageDocument>`. 첫 문서가 확정되면 이행되고, 확정할 수 없으면 거부됩니다. |
| `current` | `PageDocument \| undefined`. 갱신이 실패해도 이전 확정 문서를 유지하고, 컨트롤러를 제거하면 `undefined`가 됩니다. |
| `update(source, options?)` | `Promise<PageDocument>`. 새 세대를 시작하며 더 새로운 갱신이 시작되면 진행 중인 작업을 취소합니다. `options.signal`을 지원합니다. |
| `print()` | `Promise<void>`. 최신 작업이 끝날 때까지 기다린 뒤 마지막 성공 페이지를 최상위 문서의 격리된 스냅샷에 복사해 인쇄합니다. 확정 문서가 없거나 컨트롤러를 제거한 뒤에는 거부됩니다. |
| `destroy()` | `Promise<void>`. 세대 생성과 내보내기를 취소하고 iframe과 Core 소유 리소스를 정리한 뒤 추적 중인 작업이 끝날 때까지 기다립니다. 여러 번 호출해도 안전합니다. |

### `PageDocument`

`PageDocument`는 한 번 확정되면 바뀌지 않습니다.

| 멤버 | 타입·반환값 | 의미 |
| --- | --- | --- |
| `iframe` | `HTMLIFrameElement` | Core가 소유하는 canonical iframe입니다. |
| `generation`, `pageCount` | `number` | 확정 세대 번호와 페이지 수입니다. |
| `pages` | `readonly PageMetadata[]` | 페이지 번호, 좌우 면, 이름, 빈 페이지 여부, 크기, 본문 텍스트입니다. |
| `warnings` | `readonly PageWarning[]` | 현재 세대의 진단입니다. |
| `timings` | `{ totalMs; resourceMs; paginationMs }` | 밀리초 단위의 세대 처리 시간입니다. |
| `exportEpub(options)` | `Promise<Blob>` | 진행 중인 최신 작업을 기다린 뒤, 의미 구조를 보존한 최신 확정 원본을 내보냅니다. |

```ts
const controller = mountPageDocument(host, { html: "<h1>안녕하세요</h1>" });
const pageDocument = await controller.ready;
const epub = await pageDocument.exportEpub({
  metadata: { title: "문서", language: "ko", identifier: "urn:example:doc" },
});
```

EPUB 옵션에는 `metadata: { title, language, identifier, modified? }`가 필요합니다. `modified?`는 `Z`로 끝나는 UTC 타임스탬프이며 기본값은 `1970-01-01T00:00:00Z`입니다. `signal?`과 `limits?: { maxEntries?, maxBytes? }`도 받을 수 있습니다. 반환되는 `Blob`의 `type`은 `application/epub+zip`입니다.

### Core 유틸리티

| API | 반환값과 제한 |
| --- | --- |
| `prepareDocument(html, options?)` | `{ html, headerTemplate?, footerTemplate?, warnings }`. 동기적으로 정리하며 페이지나 iframe은 만들지 않습니다. 옵션은 `headerTemplate`, `footerTemplate`, `allowRemoteResources`입니다. |
| `pageWarningTargetBounds(pageDocument, warning)` | `{ left, top, width, height } \| undefined`. 현재 문서의 추적 가능한 경고만 좌표를 반환합니다. |
| `hasPageDocumentFrameSandbox(iframe)` | `boolean`. sandbox 토큰이 공개 상수 `PAGE_DOCUMENT_FRAME_SANDBOX`의 `allow-same-origin`, `allow-modals`와 정확히 같은지 확인합니다. |
| `selectBlankMarkers(markers, pages)` | 빈 페이지가 필요한 marker ID 배열입니다. `markers`는 `{ id, side: "left" \| "right" }[]`이고 ID를 찾을 수 없으면 예외가 발생합니다. |

## Core Publication

### `mountPublication`

```ts
function mountPublication(
  container: HTMLElement,
  snapshot: PublicationSnapshot,
  options?: PublicationOptions,
): PublicationController;
```

순서가 있는 `entry`를 하나의 페이지 순서로 조합하고 컨트롤러를 동기적으로 반환합니다. `snapshot`이 잘못됐거나 Publication 확장 기능이 실패하면 마운트 중에 예외가 발생할 수 있습니다.

`PublicationSnapshot`은 `metadata: { title, language?, identifier? }`와 순서가 있는 `entries`를 가집니다. 각 `entry`에는 `id`, `title`, 선택형 `baseUrl`, 그리고 `html` 또는 `lightDom` 중 정확히 하나가 필요합니다. Publication 제목과 각 `entry`의 ID·제목은 비어 있지 않아야 하며, `entry`가 하나 이상 필요합니다. ID는 서로 달라야 하고 공백이나 제어 문자를 포함해서는 안 됩니다.

`PublicationOptions`는 `PageDocumentOptions`와 같지만 `extensions`의 타입이 `readonly PublicationExtension[]`입니다. Publication 확장 기능은 `transformEntry`, `allowAsset`, `decoratePage`를 제공할 수 있지만 일반 페이지용 `transform`은 사용할 수 없습니다.

#### `PublicationController`

| 멤버 | 반환값과 동작 |
| --- | --- |
| `ready` | `Promise<PublicationDocument>`. 처음 확정된 Publication입니다. |
| `current` | `PublicationDocument \| undefined`. 현재 확정 문서입니다. |
| `resolveDestination(id)` | `PublicationDestination \| undefined`. 현재 세대의 `outline`이나 검색 결과 ID를 해석합니다. |
| `search(query)` | `readonly PublicationSearchResult[]`. 문서가 확정되기 전에는 빈 배열을 반환하고, 이후에는 현재 색인을 검색합니다. |
| `navigate(destination)` | `void`. 목적지 전체가 현재 세대와 일치하고 실제로 존재할 때만 이동합니다. 그렇지 않으면 예외가 발생합니다. |
| `update(snapshot, options?)` | `Promise<PublicationDocument>`. 완전한 `snapshot`을 검증하고 준비합니다. `options.signal`을 지원합니다. |
| `print()` | `Promise<void>`. 내부 Page 컨트롤러의 최신 성공 문서 인쇄 동작을 사용합니다. |
| `destroy()` | `Promise<void>`. 내부 Page와 Publication 리소스를 정리합니다. |

`PublicationDocument`는 `PageDocument`에 `metadata`, `entries`, `outline`을 더합니다. 각 `entry`의 `pageRange`는 전역 페이지 범위이며, 서로 이웃한 `entry`가 한 페이지를 공유할 수 있습니다. `outline` 항목은 `kind`, `title`, `level`, `destination`, `children`을 가집니다. `destination`에는 `id`, `entryId`, `page`, `generation`이 있습니다. 검색 결과는 `entry`, `page`, `excerpt`, `destination`을 제공합니다.

## Viewer 페이지/PDF, Reader, Inspector

### `mountPageViewer`

```ts
function mountPageViewer(
  container: HTMLElement,
  pageDocument: PageDocument,
  options?: PageViewerOptions,
): PageViewerController;
```

`pageDocument.iframe.parentElement`는 `container`여야 합니다. 옵션은 `mode?: "continuous" | "single" | "spread"`, `spread?: { cover? }`, `zoom?`, `controls?`, `theme?`, `inspector?`, `reader?`입니다. 기본값은 `continuous`, `cover: false`, `zoom: 1`, `controls: true`이며 Inspector와 Reader는 사용하지 않습니다. `controls: false`를 지정하면 표시 컨트롤러는 유지하면서 기본 조작 UI를 만들지 않습니다. 배율은 0.5–2.5로 제한됩니다. 너비가 720px보다 좁으면 요청한 spread 모드는 유지하되 `effectiveMode`만 `single`이 됩니다.

#### `PageViewerController`

| 멤버 | 반환값과 동작 |
| --- | --- |
| `goToPage(page)` | 번호를 유효 범위로 제한해 이동합니다. 유한하지 않은 값은 무시합니다. |
| `nextPage()`, `previousPage()` | 다음 또는 이전 페이지·spread로 이동합니다. |
| `setZoom(zoom)` | 0.5–2.5, 0.1 단위로 배율을 바꿉니다. |
| `setMode(mode)` | continuous, single, spread를 선택합니다. |
| `setSpreadCover(cover)` | spread 표지 배치를 바꿉니다. |
| `setTheme(theme?)` | `--imposia-viewer-*` 문자열 사용자 정의 속성 맵을 교체하거나 제거합니다. |
| `subscribe(listener)` | 현재 상태를 즉시 전달하고 이후 표시 상태 변경을 전달합니다. 반환 함수를 호출하면 구독을 해제합니다. |
| `refresh(pageDocument)` | 같은 iframe의 더 최신 세대로 갱신합니다. 다른 iframe이나 이전 세대의 문서를 전달하면 예외가 발생합니다. |
| `print()` | 현재 canonical 페이지를 최상위 문서의 격리된 스냅샷에 복사한 뒤 `Window.print()`를 호출합니다. 컨트롤러를 제거한 뒤에는 `Promise`가 거부됩니다. |
| `destroy()` | Reader, Inspector, 테마와 이벤트를 정리하고 기존 속성을 복원합니다. |
| `state` | `{ page, pageCount, zoom, mode, effectiveMode, status: "ready", generation }`입니다. |
| `reader`, `inspector` | 옵션을 켰을 때 각 컨트롤러, 아니면 `undefined`입니다. |

Viewer CSS는 `.imposia-viewer` 안에만 적용됩니다. 호스트 앱의 `body`,
`:root`, 외부 요소, 스크롤을 바꾸지 않으며 미리보기의 크기와 배경은
호스트가 정합니다.

`validatePageViewerOptions(pageDocument, options?)`는 테마, `PageDocument` 구조, Reader 소유 관계를 검사하고 `void`를 반환합니다. 어댑터가 기존 Viewer를 해제하기 전에 새 설정을 확인할 때 사용합니다.

### Publication Reader와 딥 링크

Reader 옵션은 현재 `PublicationDocument`를 소유한 `controller`, `initialDeepLink?`, `onDeepLinkChange?`입니다.

| `PublicationReaderController` 메서드 | 반환값과 동작 |
| --- | --- |
| `openTableOfContents()`, `closeTableOfContents()`, `toggleTableOfContents()` | 목차 상태를 제어합니다. |
| `openThumbnails()`, `closeThumbnails()`, `toggleThumbnails()` | 썸네일 상태를 제어합니다. |
| `selectThumbnail(thumbnail)` | 현재 세대의 전역 페이지로 이동합니다. 이전 세대의 모델을 전달하면 예외가 발생합니다. |
| `openSearch()`, `closeSearch()`, `toggleSearch()` | 검색 상태를 제어합니다. |
| `search(query)` | 현재 확정 문서의 검색 결과 배열입니다. |
| `nextSearchResult()`, `previousSearchResult()` | 결과를 선택해 이동하거나 결과가 없으면 `undefined`입니다. |
| `selectSearchResult(result)` | 결과 목적지로 이동합니다. |
| `navigate(destination)` | Core 목적지와 Viewer 페이지를 함께 이동하고 딥 링크를 갱신합니다. |
| `restoreDeepLink(value)` | 현재 목적지로 복원해 이동하거나 `undefined`를 반환합니다. |

Reader 메서드는 컨트롤러를 제거한 뒤 호출하면 모두 예외가 발생합니다. 목차·썸네일·검색 패널 중 하나를 열면 나머지 패널은 닫힙니다. `PublicationThumbnail`에는 페이지, 세대, 크기, `previewLineCount`가 있습니다.

`serializePublicationDeepLink(destination)`은 `v1.`과 URL 인코딩된 ID를 반환합니다. `restorePublicationDeepLink(value, controller)`는 현재 목적지를 반환하며 이동하지 않습니다. 형식이나 ID가 유효하지 않으면 `undefined`입니다.

### `mountViewer`로 PDF 표시

```ts
function mountViewer(

  options?: ViewerOptions,

```

이 별도 Viewer는 PDF.js로 PDF 페이지를 불러와 이미지로 표시합니다. 옵션은 `mode?: "continuous" | "single"`, `zoom?`, `workerSrc?`, `theme?`입니다. 컨트롤러를 즉시 반환하며 `ready` Promise는 없습니다. 준비 상태는 `state.status`의 `loading`, `ready`, `error`로 확인하세요. 오류 문자열은 `state.error`에 들어갑니다.

| `ViewerController` 멤버 | 반환값과 동작 |
| --- | --- |
| `goToPage(page)`, `nextPage()`, `previousPage()` | PDF 페이지를 이동합니다. |
| `setZoom(zoom)` | 배율을 0.5–2.5로 제한하고 다시 렌더링합니다. |
| `setMode(mode)` | continuous 또는 single로 바꿉니다. |
| `setTheme(theme?)` | 인스턴스 테마를 교체하거나 제거합니다. |

## 수명 주기와 오류

| 상황 | 결과 |
| --- | --- |
| 첫 세대를 준비하는 중 | `current`는 `undefined`이고 React 상태는 `loading`입니다. |
| 문서를 확정한 뒤 갱신하는 중 | 이전 확정 문서가 화면과 React 상태에 남습니다. |
| 더 새로운 갱신 시작 | 진행 중이던 이전 세대의 `Promise`가 `AbortError`와 함께 거부됩니다. |
| 호출자가 작업 취소 | 관련 세대 생성 또는 내보내기의 `Promise`가 DOM `AbortError`와 함께 거부됩니다. |
| 문서를 확정한 뒤 갱신 실패 | `Promise`는 거부되지만 이전 확정 문서는 `current`에 남습니다. |
| 컨트롤러 제거 | 작업을 취소하고 리소스와 iframe을 해제하며 `current`를 비웁니다. |

`ImposiaError`는 `Error`를 확장하며 `readonly code: string`을 가집니다. 취소는 보고해야 할 실패와 구분해 처리하세요.

```ts
class ImposiaError extends Error {
  readonly code: string;
  constructor(code: string, message: string);
}
```

Core가 분류한 오류에는 `code`가 있습니다. 예를 들어 잘못된 페이지 크기는 `INVALID_PAGE_GEOMETRY`, 이전 세대의 Publication 목적지는 `STALE_PUBLICATION_DESTINATION`, 리소스 시간 초과는 `RESOURCE_TIMEOUT`입니다. 공개 타입의 `code`는 문자열이므로 모든 코드가 고정된 union이라고 가정하지 마세요. 구조나 호출 순서가 잘못되면 일반 `Error`나 `TypeError`가 발생할 수도 있습니다.

```ts
try {
  await controller.update(nextSource, { signal });
} catch (error) {
  if (error instanceof DOMException && error.name === "AbortError") return;
  if (error instanceof ImposiaError) console.error(error.code, error.message);
  throw error;
}
```

Viewer 메서드는 현재 상태에서 실행할 수 없는 호출을 대체로 무시합니다. 다만 소유 관계가 중요한 호출은 예외를 발생시킵니다. Page Viewer의 마운트와 `refresh()`는 canonical iframe을 검증하고, Publication 탐색은 이전 세대의 목적지를 거부하며, Reader와 Inspector는 각각 다른 세대의 썸네일과 경고를 거부합니다.

이전 세대의 `destination`, 검색 결과, 썸네일, 경고를 새 확정 문서에서 다시 사용하지 마세요. `resolveDestination()`, `search()`, Reader `state`, 새 문서의 `warnings`에서 다시 가져오세요.
