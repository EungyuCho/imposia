コンテンツを編集して印刷する機能を作ると、多くの場合「同じはず」の文書が 3 つできあがります。エディターがコンテンツを描画し、プレビューがそれを複製し、印刷経路が別の場所でもう一度組み立て直すためです。やがてプレビューは 12 ページ、PDF は 13 ページになりますが、どちらが正しいかは誰にも答えられません。どれを正とするか、何も決めていないからです。

Imposia はこの問いをなくします。手元の HTML と CSS をブラウザー内で 1 つのページ分割済み文書にし、プレビュー、ネイティブ印刷、**PDF に保存**のすべての面が、その同じ完成済み文書を参照します。

## HTML がページになるまで

1. アプリが HTML、CSS、ページ設定を Imposia に渡します。
2. Core が一時的な iframe で次の版をページ分割します。
3. ページ分割が完了すると、Imposia が表示中の文書を一度に置き換えます。

ページ分割に失敗した場合や、より新しい更新が先に始まった場合も、読者には直前に完成した文書が表示され続けます。作りかけのレイアウトが画面に現れることはありません。

## 1 つの確定したソースから作れるもの

| 出力 | 取得方法 | 受け取るもの |
| --- | --- | --- |
| プレビュー | React Viewer | canonical iframe から表示される完成済みページ |
| 印刷または PDF | `print()` | ブラウザー標準の印刷ダイアログ。読者はここでプリンターまたは**PDF に保存**を選びます |
| EPUB | `exportEpub()` | 任意の機能。ページと同時に確定した意味構造を保つソースから作るリフロー型 EPUB 3.3 `Blob` |

## 境界を確認する

<Callout type="warn" title="Imposia は PDF バイトを返しません">
`print()` はブラウザー自身の印刷フローを開きます。PDF レンダラーも、Node や CLI のレンダラーも、サーバー出版 API もありません。サーバー上で PDF バイトが必要なアプリケーションに Imposia は適していません。その場合はヘッドレスブラウザーかサーバーサイドレンダラーを使ってください。
</Callout>

Imposia はブラウザー内で動作し、ESM として提供されます。この構成がアプリケーションに合うなら、[最初のページを作る](/ja/docs/getting-started)へ進んでください。
