`@imposia/core`는 페이지 문서의 기준 런타임입니다. 페이지네이션, 수명 주기, 리졸버 경계, 확장 기능, 인쇄, 내보내기를 React 없이 제공합니다. 이 문서의 모든 API는 브라우저에서만 실행됩니다.

## Core 페이지 문서

### `mountPageDocument`

```ts
mountPageDocument(
  container: HTMLElement,
  source: PageSource,
  options?: PageDocumentOptions,
): PageDocumentController;
```

이 함수는 화면 표시와 인쇄의 기준이 되는 canonical iframe 하나를 즉시 추가하고, 세대 준비를 시작한 뒤 동기적으로 반환합니다. 첫 문서를 읽기 전에 `ready`를 기다리세요.

```ts title="app/mount-page-document.ts"
const controller = mountPageDocument(host, { html: "<article><h1>안녕하세요</h1></article>" });
const pageDocument = await controller.ready;
```

`PageSource`는 `{ html: string; baseUrl?: string }` 또는 `{ lightDom: Element | DocumentFragment; baseUrl?: string }`입니다.

| `PageDocumentOptions` 필드 | 타입과 용도 |
| --- | --- |
| `iframeTitle`, `blockedResourcePolicy`, `elements`, `fontLoading` | [0.7.0](#미리보기-준비와-html-내보내기-070) |
| `tableRowspan` | `"preserve"`(기본) 또는 `"split"`. [표 행 분할](#표-행-분할과-내보내기-픽셀-비율) 참고. |
| `css` | `readonly string[]`. 함께 적용할 CSS입니다. |
| `assetResolver` | 글꼴, 이미지, 미디어, 스타일시트 요청에 응답하는 비동기 리졸버입니다. |
| `page` | `{ size?, orientation?, margin? }`. size는 `A3`, `A4`, `A5`, `B4`, `B5`, `Letter`, `Legal`, `Ledger` 또는 사용자 정의 너비·높이를 받습니다. |
| `limits` | 입력, 노드, 에셋, 시간 제한, 페이지, 레이아웃 패스, 생성 출력의 선택적 상한입니다. |
| `headerTemplate`, `footerTemplate` | 머리말·꼬리말 장식 마크업입니다. |
| `decorateBlankPages` | 빈 페이지에 장식을 적용할지 정합니다. |
| `experimental` | `{ footnotes?: boolean; pageFloats?: boolean }`. 두 기능 모두 실험 단계이며, 제한을 벗어나면 `FOOTNOTE_DEFERRED` 또는 `PAGE_FLOAT_FALLBACK` 경고와 함께 폴백합니다. |
| `extensions` | 순서가 있는 `PageExtension` 또는 `PublicationExtension` 값입니다. |
| `compose` | `{ yieldBudgetMs?: number; scheduler?: () => Promise<void> }`. 기본 8ms 예산으로 메인 스레드에 실행을 양보하는 협조적 페이지네이션입니다. `Infinity`는 스케줄러 양보를 끕니다. |
| `signal` | 최초 세대를 취소합니다. |
| `onProgress` | 준비 단계가 페이지를 할당할 때마다 패스 기준 `{ completedPages, pass, provisional: true }`를 받습니다. 이후의 수렴 패스는 수를 다시 셉니다. |

스케줄러, 글꼴, 이미지 대기는 실제 경과 시간 기준인 `limits.resourceDeadlineMs`에 포함됩니다. 진행률은 준비 단계의 잠정 작업을 설명하며, 최신 확정 세대는 `controller.current`에서만 읽으세요.

`AssetResolver`는 `{ url, kind, baseUrl, signal }`을 받아 `{ status: "resolved", bytes, mimeType, resolvedUrl? }` 또는 `{ status: "blocked", reason? }`으로 응답합니다. 구현 방법은 [이미지와 글꼴 불러오기](/ko/docs/guides/assets)에서 다룹니다.

### 확장 기능

`PageExtension`과 `PublicationExtension`은 동기식 `finalizePage(page, context)`도 구현할 수 있습니다. 이 훅은 Core가 장식과 margin box를 붙인 뒤, 확정 전에 승인된 페이지마다 한 번 실행되므로 `page.element`는 크기를 측정할 수 있는 실제 페이지 요소입니다. `page.tableFragments`에는 이어지는 표 조각이 원본 정보, 1부터 시작하는 연속 인덱스와 함께 들어 있습니다. 변경 내용은 확정된 iframe에 유지됩니다. 훅은 `decorateBlankPages` 설정과 관계없이, 의도적으로 삽입한 빈 페이지를 포함한 모든 할당 페이지에서 실행됩니다.

<Callout type="warn" title="finalizePage는 undefined를 반환해야 합니다">
`finalizePage`가 `undefined`가 아닌 값을 반환하면 세대 전체가 거부됩니다. 이 훅은 실제 페이지 요소를 변경하는 방식으로만 동작하며, 대체 값을 반환하는 방식은 없습니다.
</Callout>

분할된 표의 이어지는 조각에 측정된 픽셀 열 너비를 고정해야 한다면 선택형 확장인 `createTableColgroupExtension()`을 사용하세요. Core는 작성된 `<colgroup>` 요소를 항상 유지합니다. 높은 행을 분할할 때는 필요한 경우 측정한 셀 너비도 고정합니다. 그 외 표의 이어지는 조각에는 이 확장을 선택적으로 사용할 수 있습니다.

### `PageDocumentController`

| 멤버 | 반환값 | 준비 조건과 오류 |
| --- | --- | --- |
| `ready` | `Promise<PageDocument>` | 처음 확정된 문서로 이행되고, 확정할 수 없으면 거부됩니다. |
| `current` | `PageDocument \| undefined` | 갱신이 실패해도 이전에 확정된 문서가 남고, 컨트롤러를 제거하면 비워집니다. |
| `update(source, options?)` | `Promise<PageDocument>` | 세대를 시작합니다. 더 새로운 갱신이 진행 중인 세대를 중단합니다. `options.signal`을 지원합니다. |
| `print()` | `Promise<void>` | 최신 작업을 기다린 뒤, 마지막으로 확정에 성공한 문서를 격리된 최상위 문서 스냅샷으로 인쇄합니다. 확정된 문서가 없거나 제거 후에는 거부됩니다. |
| `destroy()` | `Promise<void>` | 세대 생성·내보내기 작업을 중단하고, iframe을 제거하고, 리소스를 해제하고, 추적 중인 작업을 기다립니다. 여러 번 호출해도 안전합니다. |

### `PageDocument`

| 멤버 | 타입·반환값 | 의미 |
| --- | --- | --- |
| `iframe` | `HTMLIFrameElement` | Core가 소유하는 canonical iframe입니다. |
| `generation`, `pageCount` | `number` | 확정 세대 번호와 페이지 수입니다. |
| `pages` | `readonly PageMetadata[]` | 페이지 번호, 좌우 면, 이름, 빈 페이지 여부, 기하 정보, 크기, 본문 텍스트입니다. |
| `warnings` | `readonly PageWarning[]` | 현재 세대의 진단입니다. |
| `timings` | `{ totalMs; resourceMs; paginationMs }` | 세대를 만드는 데 걸린 시간입니다. 단위는 밀리초입니다. |
| `exportEpub(options)` | `Promise<Blob>` | 진행 중인 최신 작업을 기다린 뒤, 마지막으로 확정된 원본을 리플로우형 EPUB 3.3 `Blob`으로 내보냅니다. |

EPUB 옵션에는 `metadata: { title, language, identifier, modified? }`가 필요하고, `signal`과 `{ maxEntries?, maxBytes? }` 제한을 선택적으로 받습니다. 내보내기는 의미 구조 기준입니다. 페이지 래퍼, margin 장식, 생성된 카운터, 페이지 전용 실험 산출물은 제외됩니다.

### 경고

확정된 모든 `PageWarning`은 `code`, `message`, 그리고 `generation`, `entryId`, `page`를 가진 고정된 `location`을 포함합니다(값을 알 수 없으면 각각 `undefined`). 확장 기능 진단은 네임스페이스가 있는 ``EXTENSION_${string}`` 코드를 사용하고 자신의 `extension` 이름을 밝힙니다.

### Core 유틸리티

```ts
prepareDocument(html: string, options?: PrepareDocumentOptions): PreparedDocument;
pageWarningTargetBounds(document: PageDocument, warning: PageWarning): PageWarningTargetBounds | undefined;
hasPageDocumentFrameSandbox(iframe: HTMLIFrameElement): boolean;
committedFrameGeneration(frameDocument: Document): number | undefined;
selectBlankMarkers(markers: PageSideConstraint[], pages: Map<number, number>): number[];
```

- `prepareDocument`는 HTML을 동기적으로 정규화·정제해 `{ html, headerTemplate?, footerTemplate?, warnings }`를 반환합니다. 옵션은 `headerTemplate`, `footerTemplate`, `allowRemoteResources`입니다. API 장식 옵션이 내장 템플릿보다 우선합니다. 브라우저 네이티브 HTML 파서로 파싱하므로 다른 Core API처럼 브라우저 전용이며, 경고는 오류 복구 후의 문서 순서로 정렬됩니다.
- `pageWarningTargetBounds`는 iframe 뷰포트 좌표 기준의 실시간 `{ left, top, width, height }`를 반환합니다. 다른 세대의 경고나 위치가 없는 경고에는 `undefined`를 반환합니다.
- `hasPageDocumentFrameSandbox`는 sandbox 토큰이 정확히 공개 토큰 집합(`allow-same-origin`, `allow-modals`)일 때만 `true`입니다.
- `committedFrameGeneration`은 Core가 커밋 시점에 canonical frame에 찍은 세대를 반환하며, 스탬프된 세대를 아직 커밋하지 않은 프레임에는 `undefined`입니다. 아직 전달되지 않은 더 새 커밋과 실제 손상을 구분하는 데 씁니다. 페이지 marker를 읽거나 검증하지는 않습니다.
- `selectBlankMarkers`는 이전 선택을 반영해, 좌우 면 배치를 맞추는 데 빈 페이지가 필요한 marker ID를 반환합니다. 페이지 매핑이 없는 marker에는 예외가 발생합니다.

## 미리보기 준비와 HTML 내보내기 (0.7.0)

`iframeTitle`은 canonical iframe의 접근성 이름을 정합니다. 기본값은 `Document preview`이며 Viewer를 연결해도 유지됩니다. `blockedResourcePolicy`의 기본값은 `"warn"`입니다. `"error"`에서는 리졸버·검증·확장·정제 과정에서 발생한 `RESOURCE_BLOCKED` 진단이 하나라도 있으면 커밋 전에 세대를 거부합니다. 갱신에 실패해도 이전 확정 문서는 유지됩니다. 거부된 `ImposiaError.code`는 `RESOURCE_BLOCKED`이며 원본 URL이나 리졸버 메시지를 노출하지 않습니다.

`elements`는 `{ selector, resolve }` 규칙의 순서 있는 배열입니다. 확장의 원본 변환 뒤, 정제와 페이지네이션 전에 작업 사본의 body 하위 요소를 선택합니다. `resolve({ attributes, text, index, signal })`은 실제 DOM 대신 고정된 속성·텍스트 스냅샷과 0부터 시작하는 매칭 인덱스를 받습니다. `undefined`는 요소 유지, `{ type: "text", text }`는 텍스트 교체, `{ type: "html", html }`은 내부 HTML 교체입니다. `{ type: "image", bytes, mimeType, alt }` 또는 `{ type: "image", dataUrl, alt }`은 요소를 이미지로 교체합니다. 규칙과 매칭 요소는 순차 처리되므로 뒤 규칙은 앞 규칙의 결과를 봅니다. 제거된 하위 요소는 건너뜁니다. 반환된 HTML은 정제되고 이미지는 MIME·디코드·바이트 제한·확장 검사를 거칩니다. 이미지에는 기존 `class`, `style`, `width`, `height`, `id`만 복사하고 반환한 `alt`를 사용합니다.

콜백의 비동기 작업에 `signal`을 전달하세요. 취소는 세대를 중단합니다. 잘못된 선택자·콜백 실패·잘못된 데이터 URL은 `ELEMENT_RESOLUTION_FAILED`로 거부됩니다. 세대 전체의 리소스 처리 기한이 지나면 `RESOURCE_TIMEOUT`으로 거부됩니다. 두 경우 모두 이전 커밋을 유지합니다. `assetFromDataUrl(url)`은 MIME 타입을 명시한 base64 데이터 URL을 `{ status: "resolved", bytes, mimeType }`으로 디코드합니다. 에셋 검증은 별도로 수행되며 base64가 아닌 URL은 받지 않습니다.

`fontLoading: { mode: "all" }`이 기본 동작입니다. `"unicode-range"`는 원본 텍스트·장식·생성 콘텐츠에서 사용할 수 없는 범위의 폰트를 건너뜁니다. `additionalText`로 나중에 필요한 문자를 예약할 수 있습니다. 범위가 없거나 잘못되었거나, 생성 콘텐츠·따옴표·카운터·텍스트 변환을 확실히 판단할 수 없으면 폰트를 보수적으로 유지합니다. 문자 범위 필터이며 계산된 font-family나 실제 글리프 커버리지를 분석하는 기능은 아닙니다.

```ts
import { exportPageDocumentHtml, mountPageDocument } from "@imposia/core";

const controller = mountPageDocument(host, { html: '<p class="name"></p>' }, {
  iframeTitle: "청구서 미리보기",
  blockedResourcePolicy: "error",
  elements: [{ selector: ".name", resolve: () => ({ type: "text", text: "김민수" }) }],
  fontLoading: { mode: "unicode-range", additionalText: "₩" },
});
const committed = await controller.ready;
const html = await exportPageDocumentHtml(committed, { title: "청구서" });
```

`exportPageDocumentHtml(document, options?: HtmlExportOptions): Promise<string>`은 해당 확정 세대를 doctype·UTF-8 선언과 함께 직렬화하고, 해결된 바이너리 에셋을 데이터 URL로 포함합니다. `options.title`로 제목을 바꿀 수 있습니다. Viewer 표시 스타일은 제외하고 확정 페이지 레이아웃은 유지합니다. EPUB는 별도의 리플로 가능한 의미 기반 내보내기입니다. 교체되거나 파괴되거나 사용할 수 없는 세대는 `DOCUMENT_UNAVAILABLE`로 거부합니다. 진행 중인 갱신을 기다리지 않습니다. 내보내기를 시작한 뒤에는 갱신·파괴가 일어나도 스냅샷이 유지됩니다. 결과는 독립 HTML 문자열이며 PDF 바이트나 다른 브라우저에서의 동일한 레이아웃을 보장하지 않습니다.

## 표 행 분할과 내보내기 픽셀 비율

`tableRowspan`은 행을 병합한 셀(`rowspan`)이 있는 표가 페이지를 넘을 때의 동작을 정합니다. 기본값 `"preserve"`는 이전처럼 rowspan으로 묶인 행 묶음을 통째로 유지합니다. `"split"`은 묶음을 행 사이에서만 나눕니다. 행 내부는 자르지 않으며, 현재 페이지에 들어가는 행이 먼저 배치되고 나머지는 반복된 헤더와 함께 다음 페이지로 이어집니다. 다른 값을 주면 문서를 만들 때 `TypeError`가 발생합니다.

```ts
const controller = mountPageDocument(host, { html }, { tableRowspan: "split" });
```

- 병합 셀의 내용은 첫 조각에 한 번만 있고 `rowspan`은 그 조각에 포함된 행 수로 조정됩니다. 다음 조각은 남은 높이만큼의 빈 셀입니다. `rowspan="40"` 셀을 29행 뒤에서 나누면 내용이 있는 `rowspan="29"`와 빈 `rowspan="11"`이 됩니다. 내용은 반복되지 않습니다.
- 이어지는 셀은 원본 표의 논리 열 위치에 놓이므로, 시작 행이 다른 병합 셀이나 `colspan` 셀과 함께 있어도 열이 유지됩니다. 원본의 시작 행·열·`rowspan`·`colspan`은 속성을 바꾸기 전에 기록합니다.
- `tr`의 `break-inside: avoid`는 분할을 막지 않습니다. 병합 셀 자체에 `break-inside: avoid`가 있거나 바깥 요소에 `break-inside: avoid`가 있으면 묶음을 그대로 유지합니다. 강제 페이지 나누기와 헤더·푸터 반복은 이전과 같습니다.
- 이 모드에서는 분할 가능한 표를 감싼 `div`나 `ol > li` 같은 일반 컨테이너를 통째로 다음 페이지로 옮기지 않고 제자리에서 나눠, 표가 현재 페이지의 남은 공간부터 시작합니다. 원자 요소와 flex·grid·다단 컨테이너는 기존 배치를 유지합니다.
- 대체 동작: 새 페이지에서도 묶음의 첫 행이 들어가지 않거나 한 행이 페이지보다 크면 남은 행을 그대로 보존하고, 삭제하거나 무한히 새 페이지를 만들지 않으며 `UNSUPPORTED_LAYOUT`과 `PAGE_OVERFLOW`를 보고합니다. 병합 셀 내부의 내용을 나누는 기능은 지원하지 않습니다.
- 너비: `"split"`은 행을 빼기 전에 표와 열의 너비를 측정해 모든 페이지에 전달합니다. 모든 셀의 `colspan`이 1인 행 중 셀이 가장 많은 행을 쓰며, 각 너비가 양수이고 합이 표 너비와 2px 이내일 때만 사용합니다. 표 자체의 행만 대상이며 중첩 표의 행은 제외합니다. `colgroup`이 없으면 만들고, 단순한 `col` 하나씩으로 된 `colgroup`은 너비만 갱신해 클래스·배경·기타 속성을 보존하며, 그 밖의 `colgroup`은 작성된 그대로 둡니다. 열을 안정적으로 측정할 수 없는 표에는 추정한 너비를 강제하지 않습니다. `"preserve"`는 너비를 측정하거나 바꾸지 않습니다.

`exportPageDocumentHtml`은 `targetDevicePixelRatio`도 받습니다. HTML을 배치할 렌더러(예: PDF 엔진)의 픽셀 비율입니다. 비율이 낮은 렌더러는 `1px` 테두리를 한 장치 픽셀로 올림해 테두리가 두꺼워지고, 그 결과 셀이 좁아져 미리보기에서는 들어가던 줄이 넘칠 수 있습니다. 옵션을 주면 모든 `td`·`th`의 각 방향 테두리를 대상 장치 픽셀로 맞추고(최소 한 픽셀), 늘어난 만큼 셀의 padding이 같은 공간을 내줍니다(`border-collapse: collapse`에서는 방향마다 절반). 좌우에는 `1/64px`를 더 확보합니다. 값은 내보낸 복제본에만 `!important` 인라인 스타일로 적용되며 미리보기 DOM은 바뀌지 않습니다.

```ts
const html = await exportPageDocumentHtml(committed, { targetDevicePixelRatio: 0.5 });
```

값은 양수이면서 유한한 수여야 하며, 아니면 `TypeError`로 거부됩니다. 생략하면 기존 내보내기와 같습니다. 비율은 렌더러마다 다르므로 호출자가 지정합니다. 적용 범위는 셀 테두리뿐이며 표·블록·SVG 테두리는 대상이 아닙니다. 테두리가 없거나 줄일 padding이 부족한 방향은 작성된 그대로 둡니다. 글자 크기나 페이지 배율은 바꾸지 않습니다. `border-collapse: collapse` 표에서 맞닿은 경계의 실제 두께는 그 경계에 선언된 값 중 가장 큰 값이므로, 경계를 마주한 모든 셀(바깥 경계에서는 표 자체의 테두리 포함)이 같은 두께를 선언한 경우에만 보정합니다. 두께가 섞인 경계, 행·행 그룹·열에 지정한 테두리, 셀 격자를 만들 수 없는 표는 작성된 그대로 내보냅니다.

## Core Publication

### `mountPublication`

```ts
mountPublication(
  container: HTMLElement,
  snapshot: PublicationSnapshot,
  options?: PublicationOptions,
): PublicationController;
```

이 함수는 순서가 있는 `entry`들을 하나의 페이지 순서로 조합하고 동기적으로 반환합니다. 잘못된 스냅샷이나 Publication 확장은 마운트 중에 예외를 발생시킬 수 있습니다.

```ts title="app/mount-publication.ts"
const controller = mountPublication(host, {
  metadata: { title: "안내서", language: "ko" },
  entries: [
    { id: "cover", title: "표지", html: "<h1>안내서</h1>" },
    { id: "start", title: "시작", html: "<h1>시작</h1><p>첫 단계.</p>" },
  ],
});
const publication = await controller.ready;
```

`PublicationSnapshot`은 `metadata: { title, language?, identifier? }`와 순서가 있는 `entries`를 담습니다. 각 `entry`에는 공백과 제어 문자가 없는 고유한 `id`, `title`, 선택적 `baseUrl`, 그리고 `html` 또는 `lightDom` 중 정확히 하나가 필요합니다. `PublicationOptions`는 `PageDocumentOptions`와 같되 `extensions`가 `PublicationExtension[]`만 받고, `pageNumbering`이 추가됩니다. `pageNumbering: "entry"`를 주면 모든 entry가 새 페이지에서 시작하고, `counter(page)`, `counter(pages)`, `pageNumber`/`totalPages` 템플릿 토큰이 entry 안에서 셉니다. 청구서 여러 장을 한 번에 인쇄해도 각 청구서에 "Page 1 of 2"처럼 찍힙니다. 페이지 메타데이터, 이동, 검색, entry 페이지 범위, 확장의 `decoratePage` 입력, target 참조는 전체 기준을 유지합니다. 기본값 `"publication"`은 Publication 전체에 번호를 매깁니다.

### `PublicationController`

| 멤버 | 반환값 | 준비 조건과 오류 |
| --- | --- | --- |
| `ready` | `Promise<PublicationDocument>` | 처음 확정된 Publication입니다. |
| `current` | `PublicationDocument \| undefined` | 현재 확정된 문서입니다. |
| `resolveDestination(id)` | `PublicationDestination \| undefined` | 현재 세대에서 outline·검색 ID를 해석합니다. |
| `search(query)` | `readonly PublicationSearchResult[]` | 확정 전에는 빈 배열이고, 이후에는 현재 색인을 검색합니다. |
| `navigate(destination)` | `void` | 목적지 전체가 현재 세대와 일치하고 실제로 존재할 때만 이동하며, 그렇지 않으면 예외가 발생합니다. |
| `update(snapshot, options?)` | `Promise<PublicationDocument>` | 완전한 스냅샷을 검증하고 준비합니다. `options.signal`을 지원합니다. |
| `print()` | `Promise<void>` | 페이지 컨트롤러와 같은 방식으로, 마지막으로 확정에 성공한 문서를 인쇄합니다. |
| `destroy()` | `Promise<void>` | 내부의 페이지·Publication 리소스를 정리합니다. |

`PublicationDocument`는 `PageDocument`에 확정된 `metadata`, `entries`, 중첩된 `outline`을 더합니다. 각 `entry`는 포함 범위인 전역 `pageRange`를 가집니다. `PublicationDestination`은 `{ id, entryId, page, generation }`이며 세대에 묶입니다. `navigate`는 이전 세대의 값을 코드가 있는 `ImposiaError`(`STALE_PUBLICATION_DESTINATION`)로 거부합니다. 검색 결과는 `{ entry, page, excerpt, destination }`입니다.
